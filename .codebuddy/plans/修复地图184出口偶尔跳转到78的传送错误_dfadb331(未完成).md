## 用户需求

排查并修复"地图传送偶尔跳错地图"的问题。具体现象：地图 184（地鼠洞穴）的"深灰市出口"传送事件目标地图 ID 已确认正确指向 81（深灰市），但玩家偶尔会被传送到 78（常青森林）。

## 关键约束与已确认事实

- 用户已明确：地图 184 及相关传送事件的**目标地图 ID 全部正确（指向 81）**，排除"事件写错地图 ID"。
- 邻接解析逻辑确定性：`Game_MapFactory#getNewMap`/`setCurrentMap`（`005_Game_MapFactory.rb:68-112`）按 `map_connections.dat` 固定顺序返回，同一坐标永远落到同一张图，无法解释"偶尔"。
- 184 在 PBS 源文件 `map_connections.txt` 中无任何连接条目（搜 `\b184\b`/`地鼠`/`Diglett` 均为 0 条），其出口依赖事件 `pbTransferPlayer`。
- 78 与 81 直接自动连接：`map_connections.txt:135-136` → `78,North,0,81,South,8`；81 北边缘即通往 78。
- 二进制数据 `Data/Map184.rxdata`（事件）与 `Data/map_connections.dat`（编译连接）文本工具读不到，需用只读 Ruby 脚本 `Marshal.load` dump 后才能定性。

## 待验证的根因假设

- 假设 B（落点压连接口）：184→81 事件的落地坐标落在 81 北边缘附近，该边缘自动连接 78，玩家落地后偶尔向北一步即落入 78。
- 假设 E（编译数据不一致）：`Data/map_connections.dat` 中存在 PBS 源文件没有的 184 连接条目（指向 78），走到该边缘时自动传送，表现为"偶尔"。

## 技术栈

- RPG Maker XP 项目（Pokémon Essentials / 宝可梦 SP4 改版），脚本语言为 Ruby（MKXP 运行）。
- 数据格式：地图与连接数据以 Ruby `Marshal` 二进制（`*.rxdata` / `*.dat`）存储；源数据以 PBS 文本（`map_connections.txt` / `map_metadata.txt`）描述。

## 实现思路

1. **先取证，后修复（轻量、零风险）**：用一段只读 Ruby 脚本 `Marshal.load` 读取 `Data/map_connections.dat` 与 `Data/Map184.rxdata`，打印所有含 184 的连接条目以及 184 各传送事件的参数（目标地图 ID + 落地 x,y + 方向）。脚本只读取不写入，不改动工程状态。
2. **按取证结果定向修复**：

- 若命中假设 B（落点压在 81 北边缘连接口）：将 184→81 事件的落地坐标南移若干格，使其远离 81 北边缘；或在 81 北边缘对应格加墙/不可通行事件，阻断"落地即掉 78"。修改在 RMXP 的地图 184 出口事件或地图 81 的对应格完成。
- 若命中假设 E（dat 存在多余 184 连接）：在 `PBS/map_connections.txt` 同步修正（确认无 184 条目）后重新编译生成 `Data/map_connections.dat`，或清理 `.dat` 中指向 78 的 184 连接并重新编译。

3. **不改动邻接系统本身**：`005_Game_MapFactory.rb` 的 `getNewMap`/`setCurrentMap` 逻辑已确认正确，无需修改，避免引入回归。

## 实现注意事项

- 只读脚本仅用于诊断，严禁在脚本中写入/重编译任何文件；正式修复仍走 RMXP 编辑器或 PBS 重编译流程。
- 修复后需在游戏内实测：从 184 深灰市出口反复进出，确认稳定落在 81，且不会意外进入 78。
- 若两假设均不成立（dump 显示落点不在北边缘且 dat 无多余连接），则重新核对 81 与 78 连接几何及 SnapEdges 行为（`78` 带 `SnapEdges = true`，可能影响连接口贴合），必要时调整 `map_metadata.txt` 中 81 的 `MapPosition`。

## 关键代码 / 文件位置

- `Data/map_connections.dat`：编译后的连接数据，dump 核对 184 真实连接。
- `Data/Map184.rxdata`：地图 184 事件，dump 核对 184→81 落地坐标。
- `PBS/map_connections.txt:135-136`：78↔81 连接定义（根源上下文）。
